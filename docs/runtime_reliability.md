# 数据库、启动恢复与兑换交付

本轮改造保留 SQLite 和现有 API 主体，优先修复热点整表写入、应用创建副作用和兑换交付丢失。

## 启动与数据目录

继续使用标准入口：

```bash
.venv/bin/python web.py
# 或停止 WebUI 后使用 CLI
.venv/bin/python main.py --count 1
```

同一个数据库只允许一个业务进程。WebUI 不同端口和 CLI 共用数据库旁的运行锁；第二个实例会在恢复或执行业务之前退出。运行锁保持到进程退出，以免 HTTP 服务停止后仍在收尾的后台任务与新进程交错。无需删除锁文件；文件存在不代表锁仍被占用。

`create_app()` 现在仅构造应用，不打开数据库、不恢复任务。正式入口在持有数据库运行锁后执行一次启动恢复。遗留的排队、运行、暂停、停止中注册任务标记为可重试失败，界面显示“已中断”；不会自动重复注册或付款。已有账号的重试仍按现有逻辑优先补跑授权。

运行时路径可以在启动进程前显式指定：

```bash
TURB_DATA_DIR=/absolute/path/to/instance \
TURB_ENV_FILE=/absolute/path/to/instance.env \
.venv/bin/python web.py
```

`TURB_DATA_DIR` 默认仍为项目根目录，数据库、历史迁移文件和业务任务日志随数据目录隔离。`TURB_ENV_FILE` 默认仍为项目根目录的 `.env`；指定文件不存在时只使用已有进程环境变量，不搜索其他目录的密钥文件。这两个路径应在进程环境中设置，不用于配置热加载。

嵌入调用可在首次访问数据库前使用 `create_app(auth_code=..., data_dir=...)`。同一进程绑定后不能再切换到另一个数据目录。直接使用应用工厂的服务器应显式接入 `core.runtime.acquire_runtime_owner()` 和 `recover_startup(owner)`，并将所有权保留到后台工作结束；本轮仍不支持多进程 Web worker 共同写同一业务数据库。

## 数据库写入范围

以下热点已改为短事务内读取并更新目标行，使用 `BEGIN IMMEDIATE` 覆盖领取或更新的完整过程：

- 注册任务创建、重试任务创建、进度和状态更新。
- 套餐查询领取、开始及结果写回；查活领取、开始及结果写回；Codex 状态写回。
- Outlook、通用 API、IMAP 邮箱领取；四类邮箱的释放及未消耗回收。
- 域名邮箱幂等登记，邮箱 ID 在所有来源之间统一分配。

索引元数据与 JSON payload 同步写入。域名邮箱保留原有登记为 `available` 的语义。

旧导入、账号插入和其他批量 API 尚未全部迁移，部分仍会整集合保存。因此保留应用锁和单业务进程限制；这一阶段不能视为完整的多进程数据库迁移。

## 兑换交付与分批领取

`POST /api/redeem` 接受：

```json
{
  "cdk": "兑换码",
  "quantity": 1,
  "request_id": "32至128位随机字母数字下划线或连字符"
}
```

`quantity` 是 1–1000 的 JSON 整数。省略时兼容旧客户端，领取该 CDK 全部剩余名额。新客户端应提交随机 `request_id`；省略该字段仍可兑换，但无法通过原请求恢复丢失的响应。

库存领取、CDK 扣减和交付快照在同一 SQLite 事务中提交。新增的 `redeem_deliveries` 表保存请求摘要、下载凭证摘要、固定期限和交付结果，不保存浏览器的原始请求凭证。

- 同一 CDK、同一 `request_id`、同一数量：在首次提交后的 600 秒内返回原批次凭据和原下载地址，`resumed=true`，不重复扣减或触发发货后查询。
- 同一请求更改数量：返回 HTTP 409、`code=request_conflict`，需要使用原数量恢复。
- 有剩余名额并且明确领取下一批：使用新的 `request_id`，生成独立批次。
- 下载链接在固定 600 秒内可重复读取，不因重试延长期限。进程重启不影响未过期交付。
- 已过期原请求：返回 HTTP 410、`code=delivery_expired`。旧请求仍保留防重记录，绝不会因内容过期而再分配库存。有效 CDK 的响应附带当前 `remaining`，前端只在用户明确选择下一批时生成新请求；原批次需联系管理员恢复。
- 管理员撤销 CDK 后，已有交付链接也停止提供内容。

兑换页按规范化 CDK 的 SHA-256 摘要分别保存最近批次的 `{request_id, completed}`，不持久化 CDK 原文、账号密码或下载地址。摘要仅作为本地索引，服务端仍校验随机请求凭证。切换不同 CDK 或领取其他 CDK 的下一批不会覆盖未确认请求的恢复信息。提交前先保存恢复凭证；保存失败则不发送兑换请求。响应丢失或刷新后，在同一标签页重新输入原 CDK 与数量，会先恢复原批次。领取同一 CDK 的下一批前应保存当前批次凭据。

到期凭据内容会在后续兑换或访问该下载时清理，幂等摘要与领取审计保留。固定到期检查不依赖清理任务，也不依赖是否创建了其他下载。数据库和备份仍属于敏感业务数据，延续现有保管方式。

## 密码与缓存

分页和非分页账号列表统一只提供 `has_password`。新旧界面的密码查看、隐藏和复制均使用已有敏感字段接口；默认响应、HTML 属性和表格不携带密码。敏感值不保存在账号列表对象或浏览器存储中。

全部 `/api/` 响应（含错误）返回 `Cache-Control: no-store, max-age=0` 和 `Pragma: no-cache`；带版本号的静态资源仍保持缓存。

## 回归验证

统一使用 pytest 执行 Python 测试：

```bash
.venv/bin/python -m pytest -q
node --test tests/*.js
```

`tests/conftest.py` 在应用模块收集前隔离配置路径，每个测试绑定独立临时数据库、迁移输入和日志目录；默认禁止 requests/curl_cffi 真实 HTTP，测试通过显式 mock 模拟上游。自动收集仅包含 `tests`，不执行手动服务探测脚本。

新增回归覆盖 SQL 无整表删除、独立进程竞争、字段合并、事务回滚、应用创建无数据库副作用、运行锁互斥、注册中断恢复、兑换跨进程读取、响应丢失恢复、分批幂等、到期防重、密码按需展示，以及兑换页刷新/网络错误/存储错误等交互。
